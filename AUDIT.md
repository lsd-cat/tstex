# AUDIT

Findings from porting. The port reproduces TeX's behaviour, bugs included; entries here are documentation, not a fix list. See PLAN.md → Auditing the original.

## Quirks (behaviour macros depend on)

- `\expandafter`/`\csname`: an undefined name inside `\csname…\endcsname` becomes `\relax` silently; no "Undefined control sequence". (§372)
- `\divide` rounds toward zero on negative operands; `x_over_n` keeps the remainder's sign separately. (§106)
- `scan_keyword` in pdftex restores `cur_cs` when the keyword does not match; tex.web does not. Affects `\show` context after a failed unit keyword. (pdftex.web)
- `\pdfoptionpdfminorversion` is a synonym sharing `\pdfminorversion`'s code; `\show` prints `\pdfminorversion`.
- `\expanded` and `\ifpdfprimitive` exist in plain `-ini`; `\ifpdfabsnum`/`\ifpdfabsdim`, `\predisplaydirection`, `\unexpanded`, `\detokenize` only in e‑TeX mode.
- The frozen `\pdfprimitive` entry has `eq_type = ignore_spaces`, `chr = 1`; the real `\pdfprimitive` is `no_expand`, `chr = 1`.
- INITEX already sets `\pdfhorigin`, `\pdfvorigin`, `\pdfpxdimen` (1bp), `\pdfcompresslevel=9`, `\pdfminorversion=4` etc. (pdftex.web §32a); a `-ini` log therefore depends on pdftex defaults, not only tex.web's.
- `input_ln` (web2c): a line ends at LF, CR or CRLF; trailing spaces are stripped, tabs kept.
- `show_context` (pdftex/e‑TeX): the "bottom line" test is `name > 19`, and non‑top levels use `line_stack[index+1]`.
- `show_context` stops at the innermost *file* level: an error inside a file `\input` from another file shows only the inner `l.N` line, never the outer file's line. (§311)
- `\endinput` only sets `force_eof`; the rest of the current line is still read, including tokens after `\endinput`. (§362, §378)
- `\read` from a closed or out-of-range stream (n<0 or n>15 → `<read *>`) is a terminal read and a fatal error in batch/nonstop mode, after `begin_file_reading` has pushed the `<read n>` level, so the context shows an empty `<read n>` line. (§483–484)
- `\read` at end of file with unbalanced braces: "Runaway definition?" (scanner_status is `defining`), then "File ended within \read"; the stream closes, `limit:=0` is immediately overwritten by `limit:=last`. (§486)
- `\openin16`: "Bad number (16)" then the file opens on stream 0. (§1275)
- `\errmessage` long help is shown once per job (`long_help_seen`); with a non-empty `\errhelp` the help is the token list, printed after a `print_ln`, and `\newlinechar` applies. (§1283, §90)
- `\the\ignorespaces` (pdftex's `ignore_spaces:` trap in `scan_something_internal`, §413): with `chr=0` nothing happens, no error, and `cur_val`/`cur_val_level` keep whatever the previous scan left (`\count0=42 \showthe\ignorespaces` shows `42`).
- `line_break` turns a final glue node into the `\penalty10000` in place (§816): the penalty keeps the glue's subtype byte (invisible in `\showbox`).
- The page builder and `fire_up` write eqtb directly, outside the save stack: `\splittopskip` is set to each split insertion's `split_top_ptr` and restored, `\vbadness`/`\vfuzz` are forced to 10000/`\maxdimen` while `\box255` is packed, and `\leftskip`/`\rightskip` with infinite shrink are replaced in eqtb by their finite copies (§827, §1014, §1017, §1021).
- `\box n` for an insertion class starts as an empty *hbox* (`new_null_box`) while it acts as a queue, and is repacked as a vbox only when its last insertion is wrapped up (§1018, §1021).
- `\pagegoal` reads `\maxdimen` and the other page dimensions read 0 while the page is empty and no output is active (§421); `\pagedepth`=… etc. assign `page_so_far` even then, and the next box overwrites it.
- DVI font numbers above 256 use `fnt_def2`/`fnt2` (`fnt_def1+1`/`fnt1+1`) with a two-byte number (tex.ch [32.602], [32.621]). Oracle `m2-review-dvi-fonts`.
- `\font\x=name scaled n` whose size would reach 2048pt (or overflow `xn_over_d`) gives "Font \x=name scaled n scaled to 2048pt or higher" and keeps the design size; the "already loaded" test treats an `arith_error` as no match (tex.ch [30.568], [49.1260]). Oracle `m2-review-font-2048` (uses `test/texmf/big100.tfm`).

- `\pdfprimitive` of a non-expandable primitive backs up the token behind the frozen `\pdfprimitive` (an `ignore_spaces` command); inside `\edef` that frozen token is stored and the following control sequence is still expanded by its *current* meaning: `\def\relax{X}\edef\a{\pdfprimitive\relax}` gives `\a=macro:->\pdfprimitive X`. `\pdfprimitive` before a name that is not a primitive (or a character token) silently drops that token. (pdftex.web)
- pdftex.web alone puts `prim_eqtb_base=frozen_primitive+1` past `frozen_null_font`, so the primitives' eqtb copies would overlap the font identifiers; pdftex.ch moves `frozen_null_font` to `frozen_control_sequence+12+prim_size` (tex.ch's `frozen_special` takes +10). The port had `frozen_primitive` on font 1's identifier slot until M3 pass B.
- Test-author note: "Interwoven alignment preambles are not allowed" (§324, §782, §789, §791, §1131) is a fatal error that a clean file cannot reach without `\endtemplate` tricks; pinning it needs a deliberately broken alignment, so no oracle covers it.
- Test-author note: `\everycr{\message{..}}` without `\noalign` loops forever: after each `\cr` the first token of `\everycr` starts a new row (§785 `init_row`), whose `\cr` reinserts `\everycr`. Use `\everycr{\noalign{…}}`.
- A file whose `\par` typesets something loops forever at `\end` in horizontal mode (`head_for_vmode` keeps inserting `\par`); both pdftex and the port spin.

- pdftex's string primitives (utils.c, checked against the binary; oracle `m5-pdfstrings`): `\pdfescapestring` writes bytes below `!` or above `~` as three-digit octal `\ooo` (space too) and backslashes `(`, `)`, `\`; `\pdfescapename` drops NUL and writes `#XX` for bytes ≤32, ≥127 and `#%()/<>[]{}`; `\pdfunescapehex` skips non-hex characters and keeps an odd final digit as the high nibble (`414` gives `A@`). All of them see the argument as `tokens_to_string` prints it: `#` doubled, a control word followed by a space.
- `\pdfmatch` (utils.c `matchstrings`, POSIX `regcomp(REG_EXTENDED)`) is leftmost-longest (`a|ab` on `xab` matches `ab`); `subcount n` limits how many of the `\pdflastmatch` slots are filled (0: none, though the result is still 1); `\pdflastmatch` of a slot without a match, past the subexpressions or after a failed match is `-1->`. A bad pattern returns `-1` with a `pdfTeX warning: pdftex: \pdfmatch: <regerror text>` (C-library wording) and keeps the previous match's slots. Oracle `m5-pdfmatch`.
- `\pdfsavepos` in DVI mode records `\pdflastxpos = cur_h + 1in` and `\pdflastypos = cur_page_height − cur_v − 1in`, where `cur_page_height` is `\pdfpageheight` or, when that is 0, the shipped box's height+depth+2`\voffset`+2in (pdftex.web «Calculate DVI page dimensions»); `cur_h` starts at `\hoffset`. The values change only at shipout. Oracle `m5-savepos`.
- `\pdfsetrandomseed` negates a negative seed; `\pdfuniformdeviate n` gives 0 for both 0 and ±n (take_frac rounding, «Note that the call of take_frac…»). Oracle `m5-random`.
- `\openout` into a directory that does not exist is `! I can't write on file` (web2c `a_open_out` fails, then §530's prompt; in batch mode the fatal "file error in nonstop mode", after `\errorstopmode` "End of file on the terminal!"). lvt `base/github-0414`, `github-0422`.

### e‑TeX (M4)

- `\showgroups` reads `saved(-2)` for an insert group, but pdftex's `begin_insert_or_adjust` pushes the `\vadjust pre` flag after the insertion number, so every `\insert n{` and every `\vadjust{` is shown as `\insert0{` (`\insert1` for `\vadjust pre`).
- `show_save_groups` steps through the semantic nest past `nest_ptr` when the bottom group is simple: `nest[1]` is read even at the outer level, i.e. whatever list state was last saved there (zero before any). The port keeps `Engine.nest` entries after `pop_nest` for this.
- `\readline` keeps the end-of-line character: with `\endlinechar=13` each line ends in a catcode-12 `^^M`.
- After the first `\aftergroup` token of a group, later ones are prepended to the same backed-up list (one `<to be read again>` level in error contexts, not one per token).
- `char_warning` with `\tracinglostchars>1` sets `\tracingonline:=1` for `begin_diagnostic` and restores it before `end_diagnostic`, so the message also reaches the terminal and `history` is not raised to `warning_issued`.
- `\interlinepenalties0` (and the other arrays at index 0) returns the number of entries; negative indexes give 0, indexes past the end the last entry.
- `\dump` zeroes `\TeXXeTstate` in the dumped eqtb; `\scantokens` input is flushed.
- An `\edef` of `\scantokens{…}` without `\everyeof{\noexpand}` reads past the pseudo file's end: "File ended while scanning definition".
- Right after the first line's `*` (or `-etex`) switches INITEX to extended mode, the `&format` load is skipped: etex.ch's «Enable eTeX, if requested» ends `if not no_new_control_sequence then no_new_control_sequence:=true else`, and that `else` takes §1337's `if (format_ident=0)or(buffer[loc]="&")`. `*&x` therefore reads `&x` as a file name (`! I can't find file `&x'.`). Unit test in `test/unit/format.test.ts`.
- `\expanded` (pdftex.web `conv_toks`, `expanded_code`) scans its argument like `\message` (`scan_toks(false,true)`: `\protected` macros and `\unexpanded` text stay, `#` is not doubled) and inserts the list as an `inserted` token list, so the result is expanded again by whoever reads it (`\message{\expanded{\noexpand\a}}` expands `\a`). It exists in compatibility mode. Ported; oracles `m4-review-expanded`, `m4-mode-compat`. pdftex's `save_cur_string` has no counterpart (the port's string under construction is only ever spliced from a saved length).

## Known bugs in the original

- `\pdfdest … xyz` (and `fith`/`fitbh`/`fitv`/`fitbv`) inside `\pdfsetmatrix` passes `pdf_width/height/depth(p)` to `set_rect_dimens`, but `\pdfdest` sets those words only for `fitr`: the destination's corners come from whatever the node's memory held before (`hologo-example.tex`, landscape pages: `/XYZ 56.687 4137.39`). The port's whatsit fields are 0 there, so it transforms the empty rectangle at the current point; not reproducible.
- Signed 32-bit overflow in §100–108 is undefined behaviour in C; pdftex's binaries wrap, and we reproduce what they print (oracle `m1-review-int-wrap`, unit `arith.test.ts`). `xn_over_d`'s `u:=(x div @'100000)*n+…` wraps (`\count1=2147483647 \dimen0=0.99999\count1` gives `-0.5pt`, no error), and `x_over_n(-2^31, 2)` negates `-2^31` to itself (`\divide` gives `1073741824`). The compiler's UB optimisations are not uniform, so neither are we: in `xn_over_d` the negated `-2^31` behaves as unsigned `2^31`; in `mult_and_add` `-(-2^31)` does not wrap (`\multiply` by `-1` reports "Arithmetic overflow"); and §448's `abs(cur_val)>=@'10000000000` treats `abs(-2^31)` as large ("Dimension too large"). `half`'s `x+1` wraps (not observable yet). The same holds for the page builder, line breaker and shipout: `cur_height-h` (§975), `page_total-page_goal` (§1007), `height+r.height` and `dimen n-height` for insertions (§1008, §1010) and the huge-page sums `height+depth+v_offset`, `width+h_offset` (§641) wrap to 32 bits before the comparison (oracles `m2-review-page-wrap`, `m2-review-huge-page`). `abs` is again not uniform: `last_special_line:=abs(hang_after)` stores `-2^31` (§849, `\hangafter=-2^31` gives a full-width first line), while `abs(x)>=c` tests treat `abs(-2^31)` as large: `\penalty-2^31` in a paragraph is a forced break (§831), `\linepenalty=-2^31` gives `d=100000000` (§859), and `\adjdemerits=-2^31` takes the `awful_bad-1` branch (§836). Oracle `m2-review-abs-wrap`.

## pdftex vs tex.web

- Command codes and the eqtb layout follow pdftex.web: `max_command = 102`, which shifts every expandable command code relative to tex.web. pdftex's integer/dimen/token parameters and e‑TeX's slots have real eqtb places.
- `undefined_control_sequence = frozen_null_font + 257` in tex.web; pdftex uses `font_max`. We follow pdftex's layout.
- `hash_size` is tex.ch's 15000 plus TeX Live's `hash_extra = 600000`, kept as one block. No hash function is replicated: names live in two `Map`s.
- `\ifeof18` (tex.ch) is `not shellenabledp`. pdftex runs with restricted shell escape, so it is false; we report shell escape as enabled for log compatibility although no `\write18` exists.
- `print` (§59) of an unprintable character disables `\newlinechar` while printing the `^^` form (`\show^^Y` with `\newlinechar=`Y` shows `the character ^^Y`). `\message`/`\errmessage` differ through enctex (enctex1.ch, enctex2.ch): the text is built under `message_printing`, which makes `print` store the `^^` form in the string (and a raw new-line character), and the string is then printed with `print`, i.e. `print_char` per character, so `\newlinechar=`Z \message{^^Z}` prints `^^` and a line break, and the 79-column test counts `^^Z` as three characters. Oracles `m1-review-print-newline`, `m3-trip-newlinechar` (an earlier entry here blamed the binary; trip's `\show^^Y` disproved it).
- trip under TeX Live differs from Knuth's logs only in the ways listed in `test/trip-diffs.md`: `\openout` is logged (tex.ch [53.1374]), §459's help names `nd, nc` (pdftex.web), a repeated `\hyphenation` word does not count in `hyph_count` (tex.ch [42.941]), the §1334 hash line reads `out of 2100+0` (tex.ch), `\dump` prints `words of pdfTeX memory` and `indirect objects` (pdftex.web), and pdftex has more primitives (500 multiletter control sequences at trip's `\dump`, Knuth 341). `unbalanced-braces.ch`'s fatal `Unbalanced write command` is not reached by trip: its write text's extra `}` ends `scan_toks` before `\endwrite` is read, so the old §1372 error and recovery apply (same message, not fatal).
- Expansion depth limit of 10000 (`expand_depth`, tex.ch) is enforced. Capacities printed in overflow messages and the stats block follow TeX Live's texmf.cnf: `stack_size=10000`, `param_size=20000`, `save_size=200000`, `buf_size=200000`, `max_in_open=15`, `nest_size=1000`, hash `15000+600000`.

- TeX Live builds pdftex with `unbalanced-braces.ch` (David Fuchs, 2024; not in `pdftex.web`, not applied to Knuth's `tex`). `back_input` (§325) and the macro-body feed (§390) never pop an exhausted `output_text` level, so after a scan inside `\output` backs up the routine's closing `}`, error contexts show the finished `<output> {…}` line (and any exhausted levels below it, e.g. a macro that triggered the page break). `end_token_list` on an `output_text` level is `fatal_error("Unbalanced output routine")` unless §1026 allows it (`output_can_end`); §1026 first pops exhausted `backed_up` levels and then insists on a finished `output_text` level. The changefile's `\write` half is ported too: reading `\endwrite` from a token list while `mode=0` (still inside the write text's `scan_toks`) is `fatal_error("Unbalanced write command")`, and §1371 restores `mode` before the final `get_token`, so a write text with too many `}`s still gets the old §1372 error and recovery. Oracles `m2-review-output-level`, `m2-review-output-unbalanced`, `m2-ch-write-unbalanced`.

### TeX Live change-file chain (texk/web2c/pdftexdir/am/pdftex.am), one line per file

- `tex.ch0`: reorders tex.ch's integer-parameter block and banner so tex.ch applies to pdftex.web. No behaviour.
- `tex.ch`: web2c system glue; consulted since M1 (file names, capacities, `\ifeof18`, `fnt_def2`, 2048pt font check, …).
- `tracingstacklevels.ch`: `\tracingstacklevels` (int par 58). With it >0, `\tracingmacros` lines get a `~` plus one `.` per `input_ptr` level, and at or beyond the limit only `~~\cs` is printed and the `#n<-` lines are dropped; every `\input` logs `~..INPUT name.ext`. Quirk: a *negative* value suppresses the `#n<-` lines (the test is `tracing_stack_levels=0 or input_ptr<tracing_stack_levels`) but keeps the full macro line. Needed tex.ch's `make_name_string` side effect: after `\input` opens a file, `cur_area`/`cur_name`/`cur_ext` describe the file found (`.tex` included), which also feeds `job_name`. Ported; oracle `m2-ch-tracingstacklevels`.
- `partoken-102.ch`, `partoken.ch`: new command code `partoken_name=103` (`max_command=103`, every expandable code shifts by one) and `\partokencontext` (int par 59). `\partokenname\cs` sets `par_loc`/`par_token` globally (a non-cs token is ignored); the new token is what empty lines emit and what non-`\long` macros reject. `\partokencontext>0` makes `}` of `\vbox`/`\vtop`/`\vcenter` in hmode back up `}` and insert the par token instead of calling `end_graf`; `>1` does the same for `\insert`/`\vadjust`/`\output`/`\noalign` (and `\valign`'s endv). Quirk: the ch adds no `prefixed_command` case, so `\global\partokenname` is `This can't happen (prefix)`. Ported (the align/vcenter/endv cases stay unreachable until M3); oracle `m2-ch-partoken`. The format-file `undump_int(par_loc)` change is M5.
- `locnull-optimize.ch`: drops the redundant `state=token_list` test from `back_input` and §390 (`loc=null` implies it). No observable change; our tests are equivalent.
- `showstream.ch`: `\showstream` (int par 60, initial −1). If it names an open `\openout` stream, `\show`, `\showbox`, `\showthe`, `\showlists` (and e‑TeX's `\showgroups`/`\showifs`/`\showtokens`) print into that file instead, with no `error` call: `common_ending` prints a newline and resets `selector` from `interaction` (+2 if the log is open). `print_nl` always starts a new line on a write stream, so the file starts with an empty line, and `print_err("OK")` lands in the file as `! OK`. Closed/out-of-range streams fall back to the log. Ported; oracle `m2-ch-showstream` (the harness now compares `\jobname.out` with `.expected.out`).
- `zlib-fmt.ch`: gzip-compressed format files. M5 (`\dump`) only.
- `enctex1.ch`, `enctex-pdftex.ch`, `enctex2.ch`: three eqtb slots `xord/xchr/xprn_code_base` after `cur_font_loc` (followed: `math_font_base=cur_font_loc+4`), four int pars 61–64 (`\mubytein`, `\mubyteout`, `\mubytelog`, `\specialout`). Every primitive (`\mubyte`, `\noconvert`, `\endmubyte`, `\xordcode`, …) is created only `if enctex_p`, i.e. with `-enc`; without it they are undefined (`\show\mubyte` → `undefined`, checked against the binary). The always-on code paths (`read_buffer`, `print_buffer`, the `print` and `\message` changes, `write_mubyte`/`mubyte_zero` in write/special nodes) reduce to TeX's behaviour while every mubyte table is empty and the parameters are 0, which they always are without `-enc`. Nothing else ported.
- `unbalanced-braces.ch`: both halves ported (see the entry above).
- synctex set (`synctex-def.ch0`, `-mem.ch0`, `-e-mem.ch0/1`, `-rec.ch0/1`, `-e-rec.ch0`, `-pdf-rec.ch2`): `\synctex` int par at `etex_int_pars` (113, after e‑TeX's state); boxes, rules, glue, kerns and math nodes carry `sync_tag`/`sync_line`, set at creation from `cur_input.synctex_tag` and `line` (get_node does it for every node of medium size or more); recording hooks in `ship_out`/`(pdf_)hlist_out`/`(pdf_)vlist_out`/`out_form`. Ported with the C side, see M9 SyncTeX below. Oracles `m2-ch-synctex`, `m9-synctex-*`.
- `pdftex.ch`: build glue (pdfTeX banner, array allocation, dump of pdfTeX's font arrays, `-etex` switch). Log-visible only through MLTeX (not enabled in `pdftex -ini`: a missing character in `hlist_out` would now be skipped without warning, unreachable without MLTeX) and the `\font` "already loaded" check being skipped when `pdf_font_step[f]≠0` (font expansion, unsupported). The `\pdfstrcmp`/`\pdffilesize`/`\pdfmdfivesum` etc. implementations live in C (`utils.c`), not here. Ported: the `-etex` switch is `run({ mode: 'etex' })` (`etex_p`), and a first line starting `*` enters e‑TeX mode too (the `*` is skipped).
- `char-warning-pdftex.ch`: `\tracinglostchars>2` makes the missing-character message an error with the hex code and no `!`; ours already matched. Oracle `m2-ch-char-warning` (levels 1–4).
- `tex-binpool.ch`: the string pool is compiled into the binary instead of read from `tex.pool`. No behaviour.
- eqtb integer parameters follow the chain's final order: TeX 0–54, web2c 55–64 (`\charsubdefmin`, `\charsubdefmax`, `\tracingcharsubdef` (MLTeX, never registered in pdftex), `\tracingstacklevels`, `\partokencontext`, `\showstream`, enctex's four), pdfTeX 65–101, e‑TeX 102–112, `\synctex` 113. Only `\dump` (M5) can see the order.

### M6 (PDF output)

- `pdf_set_rule`: `y - (h + 1)/2` is real division in Pascal; web2c passes the double to an integer parameter, so C truncates toward zero (`Math.trunc`), not `div`.
- `\pdfdecimaldigits` raster: every coordinate goes through `divide_scaled` and the *rounded* value is fed back (`scaled_out`) into `pdf_origin_h/v`, `pdf_h`, `pdf_v`, `pdf_delta_h`; positions drift exactly as pdftex's. `/Widths` are `divide_scaled(width, pdf_font_size, 4)` printed as C's `%i` of `w/10` and `w%10` (a negative width would print `.-3`).
- `preset_fontmetrics` (writefont.c): the italic angle `-atan(slant)·180/π` is a double passed to `dividescaled(scaled,…)`, truncated to an integer *before* dividing by the font size, so the TFM fallback is always 0; the real value comes from the Type 1 `/ItalicAngle`. `/Ascent` is the height of `h`, `/CapHeight` of `H`, `/Descent` the depth of `y`, `/StemV` a third of the width of `.` (all TFM, overridden only by keys the font has: `/StdVW`, `/FontBBox`, `/ItalicAngle`, `/FontName`; Type 1 fonts have no `Ascender`/`CapHeight`).
- `write_fontdictionary`: `(fd != NULL && tfm_name != NULL && strcmp(tfm_name, "dummy-space")) == 0` compares the whole conjunction with 0, so a ToUnicode CMap is also written for every font without a descriptor (none reach it with Type 1 fonts) and for `dummy-space`, whatever `\pdfgentounicode` says.
- Built-in glyph names are read only on the subsetting path (`t1_subset_ascii_part`): a map entry with `<<font.pfb` (no subsetting) and `\pdfgentounicode=1` stops with `builtin glyph names is empty`.
- Objects are numbered in this order at the end: per font object (newest font first) its encoding object number (first use) and its `/Widths` array (written at once); then descriptors sorted by font file name (each preceded by its font program), encodings sorted by name, font dictionaries sorted by TFM name (each preceded by its ToUnicode CMap); then the Pages tree, catalog, info. Fonts with the same TFM name at different sizes share one font object (`pdf_font_num < 0`), resource name `/F<internal font number>`.
- `/ID` is MD5 of `start_time_str` (`D:19700101000000Z` with `SOURCE_DATE_EPOCH=0`) followed by the output file name (`job.pdf`). With `SOURCE_DATE_EPOCH` the dates are UTC (`Z`).
- The default map file `pdftex.map` is read at the first font lookup, i.e. while shipping the first page that has text (`[1{…/pdftex.map}`); `.enc` files are read (and logged `{…enc}`) when a re-encoded font is first set on a page (`hasspacechar` in `pdf_init_font`); font files are logged `<path>` (subsetted map entry) or `<<path>>` at the end, sorted by font file name.
- The C back end's messages say `pdfTeX warning: <kpse_invocation_name>`; pdftex prints its argv[0] (an absolute path when run as such), we print `pdftex`, which is what the normaliser leaves of pdftex's path.
- `\pdfglyphtounicode`'s table is part of the format (`dumptounicode`); LaTeX's format loads `glyphtounicode.tex` and sets `\pdfgentounicode=1`.
- `garbage_warning` ("dangling objects discarded, no output file produced") needs `pdf_gone > 0`: with no pages it appears only if more than 16384 bytes (`pdf_op_buf_size`) of objects were written, or a stream was (every stream end flushes). A hyperref document with an empty body only says `No pages of output.` (and pdftex leaves a 0-byte PDF). Oracles `m6-review-dangling`, `m6-review-dangling-small`.
- `fix_pdf_draftmode` runs inside `fix_pdfoutput`, i.e. at every shipout also in DVI mode: `\pdfdraftmode` is frozen at the first one, a later change is the fatal `\pdfdraftmode can only be changed before anything is written to the output`, and a frozen value > 0 assigns `\pdfcompresslevel=0` (unsaved, also in DVI mode). `check_pdfversion` first stores `fix_int(\pdfdraftmode, 0, 1)` in the same variable, so `\pdfdraftmode=2` before the first PDF shipout is that fatal error. With draft mode on no image or font is written, no PDF file is made, and the run ends with `pdfTeX warning: \pdfdraftmode enabled, not changing output pdf`. Oracles `m6-review-draftmode*`.
- `\pdfobj useobjnum n` refuses (warning, `\pdfretval=-1`, fresh object) a number whose `obj_aux` is set, and `obj_aux` is also `obj_annot_ptr`/`obj_dest_ptr`: a reserved annotation number becomes unusable once that annotation has been shipped. Oracle `m6-review-obj-useobjnum`.
- The `\pdfcolorstack` "not initialized" help line reads `Allocate and initialize a color stack with \\pdfcolorstackinit.`: the WEB pool string keeps both backslashes. Oracle `m6-review-colorstack-help`.
- kpathsea names `.map` and `.enc` files found in the current directory without `./` (`{my.map}`, `(file my.map)`), while font and image files keep it (`<./mycm.pfb>`, `<./img.png>`); a map or encoding file the run itself wrote with `\openout` is found. Oracle `m6-review-enc-notdef`.
- `write_enc`: a used slot that the encoding leaves undefined is written as `/.notdef` in `/Differences`. Oracle `m6-review-enc-notdef`.
- PDF images: xpdf clips the CropBox (and the Bleed/Trim/ArtBox, which default to the unclipped CropBox) to the MediaBox and nothing else; poppler's rule of replacing a too-wide CropBox by the MediaBox's extent does not apply. Messages of `read_pdf_info` carry `(file ./x.pdf)`. Oracles `m6-review-pdfimage-*`.
- PNG: `write_png_palette` always creates and writes the palette object, also when `colorspace` makes the image ignore it (an unreferenced object). Decoded rows of 1/2/4-bit images have zero padding bits after the last pixel (libpng combines each row into a fresh buffer), while the filters of the next row use the file's bits. Chunk CRCs are checked up to the first IDAT: a bad critical chunk is `libpng: internal error`, a bad ancillary chunk is silently dropped (pdftex's libpng warning handler prints nothing). Oracles `m6-review-png-palette`, `m6-review-png-crc`.
- PNG alpha: below PDF 1.4 `png_set_strip_alpha` writes plain gray/RGB; from 1.4 on the alpha samples become an `/SMask` image (16-bit alpha keeps its high byte) and `read_png_info` allocates one transparency group object per run and stores the *current* `pdf_page_group_val` as the image's group, which outside a shipout is the value the last page left (0 after a page without such image, so then the run's group object). That object (`<</Type/Group /S/Transparency /CS/DeviceRGB /I true>>`, after a `%PTEX` comment when uncompressed) is written after the first alpha image. Oracles `m6-review-png-alpha*`.
- PNG transformations (`write_png`): every `tRNS` image goes through `png_set_tRNS_to_alpha`, so palette images with `tRNS` become 8-bit RGBA (never `/Indexed`) and low-bit gray with `tRNS` 8-bit gray+alpha. The writer is chosen by the colour type *after* the transformations, but `png_set_strip_alpha` (below PDF 1.4) and the page group (`read_png_info`) by the file's: below PDF 1.4 a `tRNS` image writes its RGBA (or gray+alpha) rows unchanged as `/DeviceRGB` (`/DeviceGray`) with `/BitsPerComponent 8`, a stream 4/3 (2×) too long for its dictionary; from 1.4 on it gets an `/SMask`, but no transparency group unless an alpha-channel PNG was read before. `fixedimagehicolor` is set to 0 by every `write_png` below PDF 1.5 and stays 0. `\pdfimageapplygamma`, `\pdfgamma`, `\pdfimagegamma` and `\pdfimagehicolor` are fixed at the first image or shipout, so changing them later has no effect (`m8-png-variants` changes them after its first image). Oracles `m8-png-*`.
- PNG gamma: the file gamma is the `gAMA` chunk only (an `sRGB` chunk does not make `png_get_valid(PNG_INFO_gAMA)` true), else `1000/\pdfimagegamma`; the correction is applied only when `screen·file` is more than 5% from 1 (`png_gamma_threshold`), so `\pdfgamma=2200` leaves a `gAMA 0.45455` file alone. A 16-bit file stripped to 8 bits is corrected through `png_build_16to8_table` with exponent `1e10/round(1e15/(file·screen))` (219998 for 2.2, not `png_product2`'s 220000: measured on a 16-bit ramp), 11 significant input bits; with `\pdfimagehicolor` the 16-bit table keeps all bits unless `sBIT` says fewer. Interlaced images: rows of sub-byte depth keep zero padding bits (pdfTeX's row buffers are fresh allocations).
- `read_jpg_info` reads through a C stream: `feof` is only checked before reading the next marker, and the seek over a segment clears it, so a JPEG ending after a segment gives `no marker found`, not `premature file end`. Oracle `m6-review-jpeg-trunc`.

### M8 (PDF inclusion, pdftoepdf.cc on xpdf)

- Type 1 subsetting (`writet1.c`): the subset tag is utils.c `make_subset_tag`: MD5 of the glyph names in `strcmp` order, each followed by a space, then the font's `/FontName`, then the round number `j` as a 4-byte native (little-endian) int; `a[0]` is the sum of digest bytes 0–12, `a[i] = a[i-1] - d[i-1] + d[i+12 mod 16]`, letter `a[i] mod 26`. A tag already used in the run (by any font) retries with `j+1`; from round 3 on a warning says so. The tag is written over a placeholder `ABCDEF+` in the `/FontName` line once the encoding has been read.
- Subrs policy: Subrs 0–3 are always kept (marked without parsing); after marking, the array is written up to the highest used index, every unused entry below it replaced by a `lenIV`-byte prefix plus `return` (encrypted with r=4330, the `RD`/`NP` token pair of the first Subr), and the `/Subrs N` count becomes that index + 1. `/Subrs 0` drops the `/Subrs` line and everything up to `/CharStrings`. A Subr missing from 0–3 is written as the bare `dup i 0` (no data). Fonts whose Subrs are not followed by `/CharStrings` within 5 lines are "synthetic": everything is kept. Subrs are re-parsed on every call (to keep the operand stack right), CharStrings once; a Subr not ending in `return` gets one appended (with a warning each parse until it has it).
- `cs_mark` follows `callsubr`, `seac` (StandardEncoding names of the base and accent; both are added to the CharSet, `/.notdef` included when the code has no standard name) and `callothersubr`/`pop` hint replacement (the argument of the last `OtherSubrs[3]` call is what `pop` pushes; that value and the operand stack are static, never reset between glyphs or fonts). Glyph marking walks the glyph tree in `strcmp` order and visits names `seac` inserts after the current one (libavl's traverser follows insertions), so a missing accent glyph is warned about twice when its name sorts later.
- The encoding written for a non-StandardEncoding font is `dup <first code of the name> /<name> put` per used glyph in name order (not code order), `dup 0 /.notdef put` when no glyph matched; `/UniqueID` lines are dropped (in the cleartext only when the line ends in `def`). For a font with its built-in encoding, a used code without a glyph name adds `/.notdef` to `/CharSet` (oracle `m8-subset-quirks`); `\pdfomitcharset=1` omits `/CharSet`.


- Resources are copied with every `pdf_newline`/`pdf_puts` quirk: `copyOtherResources` and the inline `/Font` dictionary end without a newline, so consecutive resources are glued (`>>/Pattern <<`), copied font references end `R` (`/F1 12 0 R/F2 13 0 R>>`) while replaced ones end `R ` (`/F1 12 0 R >>`), and `/Group N 0 R` follows a copied `/PieceInfo` dict on the same line. `pdf_newline` looks at `pdflastbyte`, which `pdfout` (names, string bytes) does not update. Oracles `m8-epdf-*`.
- xpdf merges a page's `/Resources` into its parent's (PageAttrs): only dictionary-valued entries survive the merge, so an inherited `/ProcSet` array (or a non-dict `/Subtype`) is dropped as soon as the page has its own `/Resources`; without the merge, `dictGetVal` dereferences each resource and indirect subdictionaries are written inline.
- Fonts: an included Type 1 font with `/FontFile` (or Type1C `/FontFile3`) whose `/BaseFont` (subset tag and `-Slant_`/`-Extend_` suffixes read off) names a map entry with an existing included font file is replaced: its descriptor is pdfTeX's own (shared with TeX's use of the same font file, so `/Ascent`, `/CapHeight`, `/Descent` come from the font's `/FontBBox`, not the TFM, when the figure is shipped first), `/BaseFont` becomes an indirect name object, `/Encoding` a new `/Differences` object built from xpdf's view of the font (font file's `/Encoding` as FoFiType1 parses its first 100 lines, then the PDF's `/Differences`). `epdf_write_enc` compares glyph names with pdfTeX's `notdef` pointer, so a `.notdef` name from the file is written. Encodings are written newest first (a prepended list). `\pdfinclusioncopyfonts=1` (fixed at the first shipout) copies instead.
- Numbers: integers as `%i`, reals by `convertNumToPDF` (6 decimals, `+0.5e-6` then truncation, trailing zeros dropped, `|x|<0.5e-6` is `0`; a real ≥ 2^31 hits C's `(int)floor`: x86 wraps to INT_MIN, we match the arm64 build we test against, which saturates to INT_MAX, after which the fractional part is ≥ 10^6 and only its last 6 digits are written, `12345678901.5` → `2147483647.483647`, `2147483647.9999999` → `2147483647.`); `/BBox` and `/Matrix` by `%.8f` + `stripzeros` (exact decimal ties round to even, as glibc does). Strings without NUL are literal with `\ooo` for bytes below 32 or above 127 (127 itself raw), others hex in lowercase; names escape every byte but `[0-9A-Za-z_.+-]` as `#XX`. xpdf's lexer reads `1e5` as `1` followed by the command `e5` (which "cannot be copied"), `--5` as 0, `5-3` as 5.
- A single content stream is copied undecoded with its `/Length` (the dictionary's value, even when xpdf found the stream shorter or longer), `/Filter`, `/DecodeParms`; a `/Contents` array is decoded and joined into one new stream with a newline between streams unless one already ends in a newline. A broken xref makes xpdf reconstruct it by scanning; then every stream's length is up to the next `endstream` (the line end included), and a stream whose `endstream` is not where `/Length` says gets 5000 more bytes.
- The `PdfDocument` keeps the copied-object list while images of the file are pending; after the last one is written (`occurences < 0`) the list is dropped, so a later page re-copies everything. `deleteimage` returns at once in `-ini` mode, so there every image of a file shares one list for the whole run.
- `/Rotate` is inherited, normalised into 0..359 by xpdf; only multiples of 90 give a `/Matrix` (and `, page is rotated N degrees` in the log). A non-integer `/Rotate` is ignored. The page group gets its object number in `out_image`; the first PDF with a `/Group` on a page writes it as that separate object, any later one copies it inline after the warning `multiple pdfs with page group included in a single page`.
- pdftex 1.40.29 crashes (SIGSEGV) on a page tree whose `/Kids` contains its own node; we report what xpdf's loop check leads to.

### M8 microtype (font expansion, protrusion, interword adjustments)

- The `\lpcode`/`\rpcode`/`\efcode`/`\knbscode`… tables live in `pdf_mem` (256 words each, allocated on the first assignment to a font, so `PDF statistics` counts 256 extra words per table touched) and their base pointers in per-font arrays that pdftex.ch re-initialises to 0 after undumping: `pdf_mem` is dumped, the pointers are not, so codes set in INITEX are lost when the format is loaded. The port keeps the arrays outside the format. Oracle `m8-fontcodes`.
- `\pdfnoligatures\f` removes the `lig_tag` of every character in `f`'s `char_info` words (font memory, so it is dumped), which disables kerns too: `\pdfnoligatures\tenrm` turns off `AV`'s kern. `\tagcode` ≤ −1/−2/−4 clears lig/list/ext tags the same way. A `\pdfcopyfont` copy has its own `char_info` words; `\letterspacefont` reads the TFM again (ligatures back) unless `nolig` follows. Oracle `m8-interword`, `m8-fontcodes`.
- `\pdfcopyfont` sets `font_area` to `///...` so `\font` and expansion lookups never match the copy; `\letterspacefont` widens every width by `round(e/1000 em)` and makes a one-font virtual font whose packet for each character is `right4 w, setchar c, right4 w` with `w = round(e/2000 em)` encoded as a fix_word against the size (`vf_replace_z`) and decoded at shipout by `store_scaled_f`; its name gets `+Nls`/`-Nls`. A font whose name ends in `[+-]digits ls` and is virtual counts as letterspaced for `\pdfcopyfont`'s check.
- An expanded font (`expand_font`) is a new internal font named `name+N`/`name-N` (`N` in thousandths), found again by name and size (`tfm_lookup`) or created: with `autoexpand` a copy of the widths, italic corrections and kerns scaled by `round(x·(1000+N)/1000)` sharing everything else, without it the TFM `name+N.tfm` is loaded (an error if it does not exist: `Font \csname\endcsname=cmr10+28 at 12.0pt not loadable`). `\font` never reuses a font with a nonzero expansion step.

- `\pdfadjustinterwordglue>0` makes every space in horizontal mode the normal interword glue: the space factor is ignored (no `\xspaceskip`, no extra space after a period; `\spacefactor3000{} ` still gives a plain space), and `\knbscode`/`\stbscode`/`\shbscode` of the character before the space are added in `quad/1000` units; a negative `\stbscode` can make the stretch negative (`plus -1.33334`). The character is found through an auto kern (`save_tail`) but not through a font kern or a ligature's boundary. Oracle `m8-interword-dvi`.
- `get_auto_kern` (`\knbccode`/`\knaccode` with `\pdfprependkern`/`\pdfappendkern`): a kern before the first character of a word jumps to `main_loop_move` and so skips the font's left-boundary ligature/kern program; a kern between two characters replaces their lig/kern lookup for that pair (`main_lig_loop` jumps to `main_loop_move`). `\-` gets the hyphen's kerns inside its pre-break list. Auto kerns are `subtype 3`, shown `(for \pdfprependkern/\pdfappendkern)`, and are skippable at the margins for protrusion.
- Protrusion (`\pdfprotrudechars`): with `>1` `try_break` adds `total_pw` (left `\lpcode` of the first visible character after the previous break, right `\rpcode` of the last before this one; discardables, empty boxes, font kerns, auto kerns, penalties, zero-width math and non-image whatsits are skipped, hboxes are entered) to the shortfall; with `>0` `post_line_break` puts `\kern-w (left margin)`/`(right margin)` nodes inside the line (the right one before `\rightskip` and before `\parfillskip` on the last line). `\unhbox`/`\unhcopy` drop margin kerns. With font expansion, `cal_margin_kern_var` evaluates the right character with `left_pw` too (pdftex's macro is shared), and `\rightmarginkern` of a last line reads 0 because the `\parfillskip` glue stops the search. Oracles `m8-protrude`, `m8-protrude-dvi`. When the protruding character is a ligature, `last_rightmost_char` (or `last_leftmost_char`) is `lig_char(p)`, a word inside the ligature node: `is_char_node` is false and its `type` is the font number, so in `try_break`'s marginal-kern variation (`cal_margin_kern_var`, expansion with `\pdfprotrudechars>1`) its own `left_pw` is 0 while the expanded copy's is not (`authorindex.tex`, an `''` at a line end; oracle `m9-review-protrude-lig`).

- Expansion in `try_break` (`\pdfadjustspacing>1`): `active_width[7..8]` sum each character's `round(Δwidth·ef/1000)` against the font's stretch/shrink instance and each font kern's change (`kern_stretch` looks the pair up in the expanded font; the previous character comes from `prev_char_p`). When the line's font stretch exceeds the shortfall, the shortfall becomes `(stretch div (max_stretch div step)) div 2`, half the stretch of one step, however small the real shortfall was; otherwise the font stretch is subtracted. All fonts of a paragraph must share the step and limits (`pdf_error`). With `\pdfadjustspacing=1` the breaks ignore expansion but `post_line_break` still packs with `cal_expand_ratio`. Oracles `m8-expand`, `m8-expand-dvi`.
- `hpack(…, cal_expand_ratio)` returns early for a stretched (shrunk) line with finite glue when the font stretch (shrink) is positive: `font_expand_ratio = divide_scaled(x, font_stretch, 3)` (thousandths of the full stretch, clipped to ±1000), then the list is packed again with `subst_ex_font`: every character gets the expanded instance for `round(ratio·ef·limit/10^6)` (C `extxnoverd`), rounded to a multiple of the step (`step·round(x/step)`) or capped at the limit, so characters with different `\efcode`s get different instances; font kerns between characters are re-read from the expanded font when they change, margin kerns are recomputed. The second pass reports under/overfull boxes, the first never does.
- PDF: an `autoexpand` instance shares the base font's object (`/Widths` are the base font's); the text is set with `1+N/1000 0 0 1 x y Tm` at every change of expansion (and once back to `1 0 0 1`), and inside it the `TJ` offsets and `pdf_delta_h` are computed in unexpanded units (`round(x·1000/(1000+N))`). In DVI the instances are fonts named `cmr10+20` whose `fnt_def` checksum pdftex never sets (uninitialised memory; the port writes 0).

- Virtual fonts (`do_vf`, `do_vf_packet`, needed by acmart's Libertine T1 fonts): pdftex reads a font's `.vf` the first time a character of it is shipped (or `\pdffontname` etc. names it, which then refuses it with `command cannot be used with virtual font`). Local fonts are looked up by name and size before being loaded; checksum/design-size/width mismatches only print a line (`checksum mismatch in font X.vf ignored`). Packets are re-encoded when read (font changes as `fnt_num`/`fnt1`, `xxx` with a one-byte length, so a special longer than 255 bytes in a packet is cut to its length mod 256). An `autoexpand` instance of a virtual font gets fresh auto-expanded copies of the local fonts (not shared with other instances). Oracle `m8-latex-acmart`.
- `\pdfobj file` copies the file found by `kpse_find_file(…, kpse_tex_format)` and logs `<<name>>`; a non-stream object gets a final newline if the file lacks one. `\pdfcreationdate`, `\year`, `\month`, `\day`, `\time` under `SOURCE_DATE_EPOCH`+`FORCE_SOURCE_DATE` are UTC (the port used local time before; hyperxmp's XMP dates and InstanceID showed it).

### M9 \ignoreprimitiveerror

- Bit 1 (`is_bit_set(n, 1)`: `n mod 2 <> 0`, so −1 counts) turns the `\vsplit` "Infinite glue shrinkage found in box being split" error into `print_ignored_err`: a log-only line `ignored: …` with no help and no error count. `wlog_cr` and `wlog('ignored: ')` do not touch `file_offset`, so the message wraps by whatever was on the log line before (oracle `m9-review-ignore-primitive-error`; LaTeX sets the bit, `changebar`'s tests hit it). It is the only error pdfTeX 1.40.29 lets the parameter ignore.

### M9 interword spaces (`\pdfinterwordspaceon`, `\pdffakespace`, `\pdfspacefont`)

- With `gen_faked_interword_space` on, `pdf_begin_string` treats a horizontal move as a space when `space(f) > 1bp`, the move exceeds `space - space_shrink - 1bp/10` and the baseline does not change: a font with a real `space` glyph at 32 (by its map encoding; `> 1bp` wide) gets a `( )` inside the string and the move is reduced by `round(w/10)` of the glyph's 4-digit width; otherwise the string is ended and `( )Tj` set in the dummy font, then the font is reselected. The font switch is delayed while the flag is on and both fonts are used (`font_used`). The dummy font (`\pdfspacefont`, default `pdftexspace`) is read with `read_font_info(null_cs, name, "", -1000)` at its first use, which also adds the map line `=pdftexspace PdfTeX-Space <pdftexspace.pfb` (mapfile.c `pdfmaplinesp`) whatever `\pdfspacefont` names, so `\pdfspacefont{dummy-space}` uses dummy-space's own `pdftex.map` entry. `\pdffakespace` sets one dummy space with the flag cleared. Oracles `m9-review-interwordspace` (plain: cmr10 without and 8r Times with a space glyph, boxes, vlists) and `m9-review-interwordspace-latex` (`times`, `\pdfspacefont{dummy-space}`, `\pdfgentounicode=1`).

### M9 SyncTeX (synctex.c, TeX Live trunk = the 1.40.29 binary's formats)

- File: `SyncTeX Version:1` (or the CLI option value if larger), `Input:` lines, `Output:pdf|dvi`, `Magnification:`, `Unit:1` (always: `SYNCTEX_UNIT_FACTOR` is 1, coordinates are sp), `X Offset:`/`Y Offset:` 0 in PDF mode and 4736287 (1in) in DVI mode, `Content:`, then per page `!N` anchor, `{page` … `!N`, `}page`, and `!N Postamble: Count:N !N Post scriptum:`. `!N` is the byte count since the previous anchor (the first counts from the file start); `Count:` counts the records written through `SYNCTEX_RECORD_LEN_*` plus anchors, not `x` records, `Input:` lines or the header. `[`/`]` are vboxes and `(`/`)` hboxes (not the other way round), `v`/`h` void boxes, `k` kern, `g` glue, `$` math, `r` rule, `x` the point after a run of characters, `f` a `\pdfrefxform`.
- `\synctex` values: nonzero turns recording on, but synctex.c only opens the file at the first `\input` or shipout after it became nonzero, and `Input:` lines are written only while the file is open, so files read before (`plain.tex` in `m9-synctex-plain`) have tags but no `Input:` line; tag 1's name is kept from the start. A shipout with `\synctex=0` before the file is open disables SyncTeX for the rest of the run (`synctex_prepare_content` aborts): `\synctex=1` after the first page does nothing but print a one-shot `-synctex=0` warning to stdout (oracle `m9-synctex-late`). Once open, `\synctex=0` stops node records but not the `{N`/`}N` sheets. In the document `\synctex` always gzips; only the CLI `-synctex=-N` writes an uncompressed `.synctex`, `-synctex=N` with bit 2 a gzipped file without `.gz`, bit 4 `<`/`>` form records, bit 8 `=` for a repeated v (ported, untested), `-synctex=0` disables it for good. The CLI option also sets `\synctex` (to N|1) at the first `\input`.
- Quirks reproduced: a kern record prints the context's h/v, which `synctex_kern` never updates (the h of the last box/glue/math record, so `k4,1:15081785,...:-54614` sits left of where the kern is); the first kern of a list is only recorded when a later math node, void hbox or kern with another tag/line flushes it, and glue, rules, boxes and list ends drop it; glue, kern, rule and `x` records ignore the form test, so the contents of a form shipped inside a page are partly recorded (`m9-synctex-forms`), while box and math records inside forms are not; math and box records have no tag>0 test (`$0,0`), glue/kern/rule records do; `x` records reuse the last record's tag and line (`x0,0` for text in a form before any record). Every shipped form writes an anchor even without bit 4. Kerns from ligature/kern reconstitution (§913) get tag 0 and are never recorded; a copied rule gets the tag and line of the copy, copied boxes, glue, kerns and math keep theirs.
- etex.ch `Handle a glue node for mixed direction typesetting` (eTeX mode, any `\TeXXeTstate`): in `hlist_out`, glue that stretches or shrinks in the box's order becomes a kern of its rounded width (leaders get a rigid spec). No PDF/DVI effect, but SyncTeX records such glue as `k`; ported in `etex.ts` `round_mixed_glue` (LaTeX's interword and `\parfillskip` glue).
- `Input:` names: generic_synctex_get_current_name is `getcwd()/` + the kpathsea name (`/private/var/…/./file.tex`) unless absolute. The engine has no cwd: `run({ cwd })` supplies it (the CLI passes the input file's directory, the oracle harness reads pdftex's from the expected `Input:1:` line); without it (library, browser) names stay as found (`./main.tex`, bundle paths). Output-directory and quoted-jobname forms are not ported (there is no `-output-directory`; a quoted jobname's file is named after the unquoted job name).
- The `.gz` is a gzip member written by `src/synctex.ts` around `TexFS.compress`'s deflate stream (level 6, mtime 0, OS 3); bytes differ from zlib's `gzopen`, the content is compared after gunzip. pdftex's stdout lines (`SyncTeX written on X.` when not in batch mode, the warnings) go to `Engine.terminal`; nothing goes to the log.

## Port deviations (deliberate; each has a `// §NNN` or `shortcut:` comment in code)

- Token memory is numeric `info`/`link` arrays with a free list; `null = 0`, fixed heads `temp_head=1, hold_head=2, backup_head=3, garbage=4`. `get_avail` zeroes `info` (TeX does not; harmless).
- No string pool. `print_cs` on an empty slot prints `^^@` as TeX's `text = 0` would. `new_string` selector writes into `Engine.cur_str`.
- Glue specs are TS objects in `Engine.spec[]` addressed by integer; `zero_glue = 0 = null`, as in tex.web.
- Terminal: `run({ terminal: string[] })` supplies the lines a user would type. `init_terminal` (§37: `**`, `Please type the name of your input file.`), `term_input` (§71, echoing into the log), the `*` prompt (§360) and terminal `\read` (§484) take them in order; the typed text is appended to `Engine.terminal` as a terminal echoes it, and running out is TeX's `End of file on the terminal!`. The §83 error dialogue ports only the empty answer (return); any other answer is `fatal_error("unsupported: terminal dialogue response X")`. With `terminal` the run starts in `\errorstopmode` as tex.web does; without it, it starts in batch mode and the terminal is at end of file, as pdftex with stdin from `/dev/null` (the lvt oracle): any terminal read (after `\errorstopmode`/`\scrollmode`, a §83 error prompt, `\read-1`, a §530 file-name prompt) is `! Emergency stop.` … `End of file on the terminal!`. No interrupts or `pause_for_instructions`; a typed answer to `prompt_file_name` is `unsupported: terminal input`. The §61 banner (`This is tstex, Version 3.141592653 (INITEX)`) is always written to `Engine.terminal`.
- Limits: `new Engine({ fs, limits })` overrides `error_line`, `half_error_line`, `max_print_line`, `stack_size`, `max_in_open`, `buf_size`, `param_size`, `nest_size`, `save_size`, `font_max`, `font_mem_size`, `hash_size`/`hash_extra`, `hyph_size`, `trie_size`, `trie_op_size`, `dvi_buf_size`, `expand_depth`, `main_memory`; defaults are TeX Live's texmf.cnf values. eqtb's layout stays fixed at TeX Live's (`hash_size` only bounds how many control sequences can be made; `font_max` only the font count), so a format is independent of the limits. `mem`/pool sizes have no counterpart.

- `\pdftexversion` returns 140.
- `handle_right_brace` calls `confusion` only for groups that never reach it (TeX's `othercases`).
- `nodeFS` reads only inside its roots (see Security).
- File names (tex.ch): `scan_file_name` keeps `cur_name/cur_area/cur_ext` as JS strings; `"` toggles quoting and is dropped; area ends at the last `/`, extension starts at the last `.` after it. Braced names (`\input{...}`, tex.ch `scan_file_name_braced`): the text is expanded (`scan_toks(false,true)`), turned into a string by `show_token_list` and fed to `more_name` with `stop_at_space` off. - The command-line file goes through the real `start_input`/`scan_file_name` on the `**` line; a missing main file now gives TeX's "I can't find file" + fatal error instead of a JS exception.
- Expansion depth: the JS stack runs out after roughly 1500 nested `expand` calls (node's default stack), far below `expand_depth=10000`. Past depth 100 `expand` probes for JS stack headroom and reports `TeX capacity exceeded, sorry [expansion depth=10000]` in the same state pdftex would, so the log matches pdftex's for runaway recursion; legitimate nestings between ~1500 and 9999 levels (e.g. `\message{` + 2000×`\number` + `1}`) fail where pdftex succeeds. `Engine.run` also maps any stray `RangeError` stack overflow to that message.
- `\tracingstats>0` at the end prints §1334's memory block (pdftex/tex.ch form, `15000+600000` hash) with this engine's own figures: 0 strings and string characters (no pool), token-memory high water for "words of memory", `cs_count`, and the real `max_in_stack`/`max_param_stack`/`max_buf_stack`/`max_save_stack` against TeX Live's sizes; nest is 0 until M2. `tools/normalize-log.ts` drops the block (from "Here is how much…" to "… stack positions out of …") on both sides since the figures depend on mem/pool sizes.

- `Engine.terminal` collects what TeX prints to the terminal; under the forced batch mode that is next to nothing (the log is complete).

### M6 pass B (PDF features: links, dests, outlines, threads, color stacks, forms, images)

- `utils.c` `checkpdfrestore` prints the position difference with `%u`: a `\pdfrestore` 1sp to the left of its `\pdfsave` reports `4294967295sp`.
- `pdfsetmatrix` parses its argument with `sscanf(" %lf %lf %lf %lf %c") == 4`, so trailing junk is an error, but only in page mode: inside a form it returns success without parsing anything, and the matrix stack only tracks page shipouts. The matrix stack is never reset between pages (only `\pdfrestore` pops it); an unbalanced `\pdfsetmatrix` without `\pdfsave` keeps transforming link rectangles on later pages.
- `pdfshipoutbegin` calls `colorstackpagestart` after setting `page_mode := shipping_page`, and that function returns at once in page mode; it is only called when shipping a page, so the form copies of the color stacks are never reset (dead code).
- Color stacks live in C (`utils.c`), outside eqtb: not dumped in the format, not subject to grouping; stack 0 starts at `0 g 0 G` in `direct` mode, and a stack is re-emitted at a page start only when its current value differs from that default (`colorstackskippagestart`).
- Annotation rectangles: `pdf_left/top/right` share the whatsit words of `pdf_width/height/depth` (one field each here), so shipping out overwrites a link's or annotation's dimensions with page coordinates. `set_rect_dimens` under a `\pdfsetmatrix` transforms the four corners with `DO_ROUND` (`(int)(x ± 0.5)`) and takes their bounding box; `end_link` recalculates with the corners remembered by the last `matrixtransformrect` call, which may belong to another rectangle (an annotation or dest between start and end of the link).
- `push_link_level`/`append_link` call `copy_node_list` on the start-link whatsit, which copies the *rest of the list after it too* (`append_link` then drops the tail by setting `link(p) := null`, leaking it and its token references). We copy the node alone; the difference is only memory.
- Running links continue at the start of every hbox at the link's nesting level (`cur_s`) unless `\pdfrunninglinkoff` is in force; each continuation is a new annotation object (`pdf_create_obj(obj_type_others)`), flushed after the page's annotations are written.
- `\pdfdest` checks for duplicates twice: when scanned (the whatsit is dropped if a dest with that identifier was already shipped) and when shipped (`do_dest`); both warn `destination with the same identifier (name{…}) has been already used, duplicate ignored` and then `show_context`. A referenced but undefined dest becomes `[first page /Fit]` with a `(dest)` warning; a referenced but undefined thread gets a dummy bead with `/R [0 0 \pdfpagewidth \pdfpageheight]` (the parameters, 0 in plain TeX).
- Named destinations are sorted by `sort_dest_names` (Hoare's quicksort, so equal names keep an arbitrary order) comparing names after PDF string escapes (`\ddd`, `\n` …); the name tree has at most 6 kids per node, and intermediate `/Limits` come from the first and last leaf names.
- `\pdfoutline` writes its action and title objects at once (before any page), so their object numbers precede the pages'; `count` with its sign controls `/Count` through `open_subentries`. `\pdfcatalog … openaction` also writes its action object at once, even in DVI mode (only the object number is dropped there).
- `/Info`: `\pdfinfo` text suppresses pdfTeX's own `/Producer`, `/Creator`, `/CreationDate`, `/ModDate`, `/Trapped` by a substring test (`substr_of_str`), so `/Creator` inside a string value also suppresses it; but the test only looks at matches that end before the last character, so `\pdfinfo{/Title (x) /Creator}` still gets pdfTeX's `/Creator (TeX)`. Oracle `m6-review-info-key`.
- `scale_image` compares the image size with the resolution as `x / one_inch >= xr`, where `one_inch = 226` ("(1in in sp)/maxdimen"): a resolution below width/226 dpi is "too small image resolution ignored".
- PNG: the IDAT copy path (`/Predictor 10`, log ` (PNG copy)`) is taken only for gray or RGB images without any of `cHRM iCCP sBIT sRGB bKGD hIST tRNS sPLT` and with gamma 1.0 or none; palette images and the common sRGB/iCCP-tagged ones are decoded and written row by row. `pHYs` counts only when its unit is the metre (libpng returns 0 otherwise).
- JPEG resolution: JFIF density (unit 1 dpi; unit 2 dpcm × 2.54 truncated) or, when the first marker is `APP1` Exif, `XResolution`/`YResolution` as C integer division of the rationals; any other first marker gives no resolution, so `\pdfimageresolution` or 72 dpi applies.
- Images and forms have dimensions in `hpack`/`vpack`, `line_break`, the page builder, `vert_break` and the display width (§1146); other whatsits stay dimensionless.
- The C back end prints `argv[0]` in its messages; `tools/normalize-log.ts` reduces pdftex's absolute path to `pdftex`, which is what we print.
- Harness: `tools/pdf-normalize.ts` lists the objects inside an uncompressed object stream one by one (offsets dropped) and keeps an xref stream's dictionary without its offsets (beamer's PDF uses both). `base/github-0094`'s expected log was regenerated (`tools/gen-lvt.sh`): it had been normalised by an older `normalize-log.ts` that did not strip absolute paths.

Deviations and unsupported (each `fatal_error("unsupported: …")`):
- PDF image inclusion: superseded in M8 (see M8 below); `\pdfximage named` and JBIG2 remain unsupported.
- PNG decoding needs `TexFS.inflate` (Node zlib). Interlaced, `tRNS`, 16-bit and gamma-corrected PNGs are ported in M8 (see M8 Type 1 subsetting and PNG below).
- Still unsupported, none of them used by LaTeX, hyperref, graphicx, xcolor, geometry, TikZ or beamer: `\pdfuniqueresname` (needs the CRC32 of the job id string with TeX Live's version strings), `\pdfsnaprefpoint`/`\pdfsnapy`/`\pdfsnapycomp`, TrueType/OpenType/PK/Type 3 fonts, map-file subfont (`@sfd@`) entries (so neither `cannot open SFD file for reading` nor the duplicate warning for such an entry).

### M8 PDF inclusion

- `src/backend/pdfread.ts` is a minimal xpdf: lexer, parser, xref tables (`/Prev`, hybrid `/XRefStm`), xref streams (`/W`, `/Index`, PNG predictors), object streams, reconstruction (constructXRef, incl. its quirk of comparing an object-stream index with a generation), the page tree and PageAttrs. No object cache (not observable: the file does not change).
- Filters: only FlateDecode (with predictors) is decoded, which is needed for xref/object streams, `/Contents` arrays and reading a replaced font's encoding; LZW, ASCIIHex, ASCII85, RunLength there are `unsupported`. Inflate is the platform's zlib: a stream with a bad Adler-32 or corrupt data decodes to nothing, where xpdf's own inflater ignores the checksum and keeps what it decoded (seen only on damaged files, e.g. a damaged font program then gives StandardEncoding).
- Encrypted files are `unsupported` (xpdf decrypts those with an empty user password; with any other it fails with `xpdf: reading PDF image failed`).
- A replaced font's encoding is xpdf 4.06's `Gfx8BitFont` (spec/GfxFont.cc, FoFiType1C.cc, FoFiIdentifier.cc, the tables in `src/backend/xpdfenc.ts` generated from FontEncodingTables.cc/FoFiEncodings.cc): the program's kind comes from FoFiIdentifier on the decoded `/FontFile3` (else `/FontFile2`, else `/FontFile`) whatever slot it sits in, so a CFF in `/FontFile` is read as CFF and a TrueType program gets WinAnsi as default; a Mac/WinAnsi `/Encoding` or `/BaseEncoding` wins over the program's; a CFF program's built-in encoding (FoFiType1C `parse` must succeed: the private dict, CharStrings index and charset are checked) has its empty slots filled from StandardEncoding; an unidentifiable program counts as absent, so a base-14 name (blanks removed, `Arial,Bold`… aliases) gets its built-in encoding and a non-embedded Symbol/ZapfDingbats ignores a predefined `/Encoding` name. A CID-keyed CFF program makes xpdf build a `GfxCIDFont`, which `writeEncodings` refuses (`CID fonts are not supported`). Oracles `m9-review-epdf-cff`, `m9-review-epdf-cff-copy` (fixture: gs `pdfwrite` output with three `/Encoding`s edited). `epdf_mark_glyphs` (the included font's `/CharSet` joins the shared descriptor's glyph set; without one, or with a `<<` entry, `embed_whole_font`) is ported.
- Hostile-input bounds (`shortcut:`): page-tree recursion stops at depth 1000 (counted as no pages / xpdf's empty page), at most 10^7 entries per xref stream, at most 64 MiB per decoded stream, predictor rows over 64 MiB are left undecoded. A page pdftex would dereference as a null dictionary (broken page tree) is `xpdf: reading PDF image failed`. xpdf's stderr messages (`libxpdf: Syntax Error …`) are not reproduced; they do not reach the log.
- Checked: all `m8-epdf-*` and `m8-latex-epdf`; 57 PDFs from various producers (pdfTeX, Ghostscript, cairo, Skia, iText, PDFlib…) and ~1500 crafted/mutated files byte-identical to pdftex's output when both embed whole fonts (a map with `<<`), apart from the inflate case above. With the default `<` entries (subset, the included fonts' `/CharSet` merged) `m8-epdf-fonts-nested` and `m8-latex-epdf` are byte-identical too.

### M8 Type 1 subsetting (writet1.c)

- SlantFont/ExtendFont (`t1_modify_fm`, `t1_modify_italic`): the `/FontMatrix` numbers are C `float`s, slanted first (`a0+=a1·s`, `a2+=a3·s`, `a4+=a5·s`), then extended, printed `%g ` each; `/ItalicAngle` becomes `angle - atan(s)·180/π` (`%g`), and `round` of it is the descriptor's `/ItalicAngle`; with ExtendFont alone the `/ItalicAngle` line is skipped, so the TFM fallback (0) stays. `/FontName` gets `-Slant_N`/`-Extend_N` in the descriptor and, for a subset, in the font program too (a whole font keeps its own name inside). Oracle `m9-review-slantfont`.
- PFA files (`t1_pfa`): the eexec part is hex, two digits per byte with line ends skipped (a non-hex digit counts as −1, then the byte is masked), the `currentfile eexec` line ends at the space after it, and after the encrypted part a byte that is not a line end is an error unless the last decoded byte was 0 (then `00` is written). Oracle `m9-review-pfa` (subset and whole font).
- `\pdffiledump offset o length n {file}` (texmfmp.c `getfiledump`): the file is found like `\pdffilesize` (`kpse_find_tex`), the bytes from `o` (past the end: none) are written as `%.2X`; `length` 0 or a missing file is the empty string; negative values are `Bad file offset`/`Bad dump length` errors and become 0. pdfTeX refuses a dump whose hex would not fit the string pool (`pool size` overflow); the port has no pool (`shortcut:`). Oracle `m9-review-filedump`.
- `<` map entries are subset as pdftex does, PDFs byte-identical (oracles `m8-subset-exact`, `m8-subset-seac`, `m8-subset-quirks`; all `m6-*` with the default `pdftex.map`, raw bytes in `test/unit/type1.test.ts`). Hostile-font bounds (`shortcut:`; pdftex crashes or runs for ever there): at most 65536 Subrs, subroutine nesting 64, 2·10^7 charstring bytes parsed per font, more than 24 operands or a `seac` code outside 0–255 is an `unsupported:` CharString error, a charstring running past the end of the file is `unexpected end of file`.
- PNG (`writepng.c` with libpng 1.6's transformations): Adam7 deinterlacing, `tRNS` (palette, gray, RGB, 1–16 bits), 16-bit samples with `\pdfimagehicolor` (PDF ≥ 1.5) or stripped to the high byte, `\pdfimageapplygamma` with libpng's tables (`png_build_8bit_table`, `png_build_16bit_table`, `png_build_16to8_table`, `sBIT` shift, palette corrected in place) are byte-identical (oracles `m8-png-variants*`, `m8-png-gamma`, `m8-png-gamma8`, `m8-png-il`, `m8-png-il13`; fixtures `images/m8-*.png` made by a script: interlaced 1/2-bit gray, interlaced palette+`tRNS`, 4/16-bit gray+`tRNS`, interlaced 16-bit RGB, 16-bit RGB+`tRNS`, interlaced RGBA, 16-bit and 8-bit ramps; checked further over 5 gamma/version settings × 22 images). `pow` is the platform's (`Math.pow`); a 1-ulp difference to C's could flip a table entry. A gamma value libpng rejects (`png_error` after pdfTeX's `setjmp` frame is gone, undefined in pdfTeX) is `libpng: internal error`. Chunk validation is libpng 1.6.55's (the version linked into TeX Live 2026's pdftex; `spec/pngrutil.c`): there are no colourspace conflict checks any more, `gAMA` is stored unless > 2^31−1 (0 included), the first of duplicate `gAMA`/`sRGB`/… wins, `gAMA`/`sRGB`/`iCCP`/`cHRM`/`sBIT`/`hIST` after `PLTE` are dropped, `sBIT` must have the colour type's length with every value in 1..depth, `sRGB` intent ≤ 3, `bKGD` the exact length (and a valid index/level), and `iCCP` passes only with a well-formed, fully inflatable profile (and, by a 1.6.55 quirk, a chunk of at least 92 bytes). hIST's table entry says "before PLTE" (a 1.6.55 slip fixed later), so an `hIST` is only kept when it precedes `PLTE` and is empty. A rejected chunk does not count for the copy decision. `png_set_gamma` ignores both values when either is outside 0.01..100 (`unsupported_gamma`): no correction. The copy path reads chunk headers until `IEND`; a file without one is `writepng: reading chunk type failed`. Oracles `m8-review-png-*` (fixtures from the cold review).
- `tools/pdf-normalize.ts` keeps everything but the xref table/stream offsets and `startxref`; it terminates on any input (an unusable `/Length` ends the stream at `endstream`, a stream without one is a thrown error with the object number).

### M7 distribution (library, bundle, browser)
- Browser reads are synchronous XHR from the Worker (`platform/browser.ts` `syncGet`, `x-user-defined` text decoded to bytes; verified in Chromium, Firefox, WebKit). Deprecated on the main thread, still specified for workers; `shortcut:` if it is ever removed from workers, switch to SharedArrayBuffer + Atomics.wait.
- Browser compression is a pure-TS zlib (`platform/deflate.ts`): one fixed-Huffman block with greedy LZ77, so `\pdfcompresslevel>0` streams are valid but ~20% larger than zlib's and not byte-equal to pdftex's (Node keeps `node:zlib`); the inflater is complete (stored/fixed/dynamic, Adler-32 checked) and fails like zlib (empty result). The level only sets the match-chain length.
- Node over an `http(s)` bundle restarts the compile on every file missing from `~/.cache/tstex/` (Node has no synchronous fetch): a cold beamer/hyperref compile takes ~50 restarts (~30 s for m6-latex-hyperref over localhost); local bundles and warm caches do not restart.
- The bundle index is unique by basename (kpathsea's ls-R lookup keys on it): for a basename in several TeX Live directories `pack-texmf` keeps the one pdflatex's search order picks for the kind its extension implies (`.tfm` tfm, `.pfb` type1, `.map` map, ... else tex), so `\input sub/foo` forms that pick a different same-named file in TeX Live find only that one. `minimal` stores exactly the files the recorded runs resolved.
- Bundle files print in the log as their bundle path (`tex/latex/base/article.cls`) where pdflatex prints the absolute TeX Live path; `\pdffilemoddate` of bundle and user files is 1970-01-01 (no mtimes in the protocol). PDFs are byte-identical to the Node CLI's (browser test).
- `cache: 'persistent'`: the worker (not the main thread) writes fetched files to Cache Storage after each compile and loads all of them into memory at startup, so synchronous reads hit memory. Playwright's default (ephemeral) WebKit context drops Cache Storage entries on navigation; a persistent context keeps them (checked by hand, not in the test).
- `runs: 'auto'` reruns while `.aux .out .toc .lof .lot .nav .snm` outputs change, at most 4 runs; outputs of earlier runs shadow user files of the same name.
- `tools/minimal-files.txt` is recorded with `TSTEX_RECORD` from `test/oracle` m5/m6 and the hyperref, graphics and amsmath `.lvt` tests; the record holds the TeX Live file every found name resolves to, also when a test root shadows it (`test/texmf` carries copies of TeX Live TFMs such as `cmssi10.tfm`, which a first recording missed).
- `playwright` is a devDependency used only by `test/browser/`; building and using the library need only `typescript`.

## Security

Trust boundary: the `.tex` and everything it can name (`.sty`, `.tfm`, `.tcx`, format bytes) is hostile. The engine must not read outside its configured roots, write outside the job directory, or throw out of `Engine.run`.

- Reads (`nodeFS.find`/`path`/`stat`, so `\input`, `\openin`, `\font`, `\pdffilesize`, `\pdfmdfivesum file`, `\pdffilemoddate`, in every name form: plain, `{…}`, `"…"`): a name is found only in a flat root or through a texmf tree's `ls-R`, and only if its real path (symlinks resolved) is inside that root's real path; files this run wrote (`Engine.outputFiles`) and `/dev/null` (empty) are the only other readable names. Absolute names, any `..` component, NUL bytes and names the OS rejects (ENAMETOOLONG, ENOTDIR, EACCES) are simply not found, so TeX reports `I can't find file` / the empty string. This is stricter than TeX Live, whose `openin_any = a` has been a no-op since 2026 (texmf.cnf: any readable file).
- Writes (`\openout`): dvi.ts applies kpathsea's `openout_any = p` (`kpathsea_name_ok`: no absolute name, no `..` component, no component starting with `.` other than `./`); `nodeFS.writable` additionally requires the directory to exist inside the first root after resolving symlinks, the target not to be a symlink, no NUL and no component over 255 bytes; otherwise `I can't write on file`. Written files live in `Engine.outputFiles`; `bin/tstex.ts` writes them, the `.log` and the `.dvi` only inside the job directory (real path checked again) and with `O_NOFOLLOW`, so a pre-planted symlink (`t.log -> ~/.bashrc` in an unpacked tarball) is refused on stderr and the exit status is 1. pdftex would follow such a symlink.
- Format bytes: `loadFormat` checks the `tstex format 1` magic (pdftex's format_ident/size checks) and that every dumped table is present, caps the decompressed size at 128 MiB (gzip bombs), and turns any failure (bad gzip, not JSON, nesting too deep, wrong shape) into one `Fatal format file error; I'm stymied (…)` error. A well-formed format with inconsistent tables (pointers out of range) is not validated; the format is produced by `tools/build-format.ts`, so it is treated as host input, not document input.
- TFM: random bytes, a zero-length file and `lf = 0xFFFF` give `Bad metric (TFM) file` (§560 checks). TCX: random bytes are tolerated (`readtcxfile` skips what does not parse); the TCX name comes from the host.
- Resource exhaustion: hash (615000), `\scantokens`/`\input` nesting (`text input levels=15`), input stack, buffer (`\csname` of 10^6 characters) and pattern memory end in TeX's `capacity exceeded`; 10^6 pages run (2.6 s). A braced file name of 10^6 characters is now built without a spread (`end_name`), so it is "I can't find file" rather than a stack overflow.
- Main memory: `get_avail` (§120: `runaway`, then `overflow`) and `node_ref` stop at `limits.main_memory` (default 5000000, texmf.cnf `main_memory`) with `! TeX capacity exceeded, sorry [main memory size=5000000].`, as pdftex does for `\def\a{x\a}\edef\b{\a}` (formerly ~3 GB and a `RangeError` after 21 s). `shortcut:` the count is token words + node handles (`Engine.nodes`), not pdftex's mem words, so the point of overflow differs; node objects reachable only from lists (a runaway paragraph) are not counted. latex.fmt uses 437339 token words.
- Strings built from document-sized arrays (`\message`, `\errmessage`, `\pdffilesize`/`\pdfmdfivesum`/`\pdffilemoddate` names, `\pdfmatch`, `\pdflastmatch`, `\pdfescape…` results, file names) no longer use `fromCharCode(...a)`/`push(...a)` (`utils.ts` `str`, `append`), which overflowed the JS stack past ~10^5 characters and was reported as `expansion depth=10000`. Left open: none known; `def_font.ts`'s spread is over `FONT<n>` only, `hash.ts`'s is bounded by `buf_size`. Frame size matters: `\number` nests through `convert.ts`'s `run`, and two inline `for…of` loops there grew its JS frame enough that `m1-review-expand-deep` (1000 nested `\number`) hit the stack probe in the full test run; the loops live in `append` instead.
- Browser/bundle reads (`bundleFS`): the same name rules (`lookup.ts` `escapes`: absolute, `..`, NUL; `/dev/null` is not found), the index is a `Map` so `constructor`/`__proto__` are not files, user files are a flat in-memory map, `\openout` writes only to `Engine.outputFiles`. The Node URL cache refuses index paths that escape its directory. Test: `bundleFS (browser): …` in `security.test.ts`.
- No `\write18`, no shell escape primitive registered as functional.
- Hostile PDFs (`\pdfximage`) and Type 1 fonts (the subsetter): `security.test.ts` `hostile PDF: …` ×19 (`/Prev` to its own xref, `/Kids` self-loops with and without `/Count 0`, a 3000-deep `/Pages` chain, a self-referencing object stream, an xref stream with `/W [0 0 0] /Index [0 2000000000]` and one whose `/Prev` is itself, xref section `0 2000000000`, `/Count 2147483647`, `/Length 1000000000`, `/Length` naming its own object, 100000 nested `[`, 450 nested dictionaries, a 23-digit `startxref`, `0 0 R` in resources, an LZW content array, `/Predictor 15 /Columns 100000000`, an empty file, `%PDF-1.4` + garbage) and `hostile Type 1 font: …` ×8 (cmr10.pfb edited: truncated eexec, `callsubr` 30000, `seac` of a missing glyph and of code 300, 30 operands, `callothersubr` popping −3, a self-calling Subr, `/lenIV -1`): each ends in a pdfTeX error, `unsupported:` or a PDF, within 2 s, never a JS exception.
- Tests: `test/unit/security.test.ts` (`read refused: …` for 20 names incl. `../secret`, absolute, `link` (symlink out), `linkdir/secret`, NUL, 5000-character, `%`, newline, ls-R prefix mismatch `evil/bar.sty`, ls-R symlink `leak.sty`; `read refused: quoted and unbraced names`; `readable: …`; `write refused: …` for 10 names incl. `linkdir/x`, `outlink`, NUL, 300-character; `CLI writes only inside the job directory, never through a symlink`; `hostile TFM: …` ×3; `hostile TCX`; `capacity: …` ×8, incl. `capacity: main memory` and `capacity: 10^6-character strings in \message, \pdffilesize, \pdfmatch`) and `test/unit/format.test.ts` (`format bytes: round trip, then corrupt formats fail cleanly`: truncated gzip, not gzip, empty, non-JSON, wrong magic, old format, missing tables, unknown typed array, deep nesting, 130 MiB bomb).
